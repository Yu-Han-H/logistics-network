## 3. 三个子工程各管什么

### 3.1 `docs/`

只放文档，不放代码。

- `开发文档-v1.1.md`：需求、排期、核心设计、接口、测试。
- `api.md`：接口契约。前后端都按它写，字段变了先改它。
- `report/`：报告草稿、截图、性能数据。

### 3.2 `logistics-server/`

后端，负责：

- 读 `cities.txt`，建链表和图。
- 手写链表、邻接表、Prim、Kruskal、Dijkstra。
- 提供 REST API。
- 登录和角色检查。
- 控制台演示程序 `ConsoleRunner`。

不负责：页面、动画、前端路由。

### 3.3 `logistics-web/`

前端，负责：

- 登录页、城市管理、链表视图、邻接表、MST、路径查询。
- 调后端 API，画 G6 图。
- 角色菜单和路由守卫。

不负责：算法计算、数据持久化。前端只显示后端算好的结果。

## 4. 后端分层和依赖方向

```
HTTP 请求
   │
   ▼
controller/          只做参数校验、调 service、返回 Result
   │
   ▼
service/             业务编排；唯一写入口；维护 graphVersion
   │
   ├──────────────► structure/     手写链表、图
   │                   │
   │                   ▼
   │                model/          City / Edge / User
   │
   └──────────────► algorithm/      Prim / Kruskal / Dijkstra
                       │
                       ▼
                    structure/ + model/
```

**规则：**

1. 依赖只能从上往下：`controller → service → structure/algorithm → model`。
2. `controller` 不写算法，不直接碰 `structure`。
3. `service` 是唯一写入口。增删改城市都走它，改完 `graphVersion++`。
4. `structure` 和 `algorithm` 不打 Spring 注解，纯 Java，方便单元测试。
5. `model` 只放数据，不放链表指针。链表指针放 `CityNode`。
6. `dto` 只放对外字段，不暴露 `prev/next` 这类内部结构。
7. `cli`、`benchmark` 不是 Web 层，不依赖 `controller`。

**反例（不要这样）：**

- Controller 里写 Dijkstra。
- Service 里直接 `new Thread` 或写 SQL。
- `City` 里加 `CityNode next`。
- 前端自己算最短路。

## 5. 前端页面和接口对应

| 页面 | 路由 | 调用的接口 | 说明 |
|---|---|---|---|
| 登录 | `/login` | `POST /api/auth/login` | 两个预置账号 |
| 城市管理 | `/cities` | `GET/POST/PUT/DELETE /api/cities` | 管理员可写，普通用户只读 |
| 链表视图 | `/city-list` | `GET /api/cities/sorted` | 显示 `head → … → head`、prev/next |
| 邻接表 | `/adjacency` | `GET /api/graph/adjacency` | 每城一行，列邻居和边权 |
| 最小生成树 | `/mst` | `GET /api/mst?algorithm=prim\|kruskal` | 总权值 + 所有边 |
| 最短路径 | `/path` | `GET /api/paths/shortest` | 路径、代价、耗时；可切 `mode=tree` |
| 404 | `/:pathMatch(.*)*` | — | 兜底 |

**前端目录对应：**

- `src/api/`：每个后端模块一个文件，组件里不直接写 URL。
- `src/views/`：页面，按业务分目录。
- `src/components/layout/`：整体布局和菜单。
- `src/components/graph/`：G6 图组件。
- `src/router/index.js`：路由 + 登录守卫。
- `src/stores/user.js`：当前用户和 token。
- `src/utils/auth.js`：token 存取。
- `src/mock/`：后端没写好时先用 mock。

## 6. 一次请求怎么走

以“查广州到北京的最短路”为例：

1. 页面 `PathView` 调 `src/api/path.js` 的 `getShortestPath(1002, 1000)`。
2. axios 实例 `request.js` 加上 `Authorization`，请求 `/api/paths/shortest?from=1002&to=1000`。
3. Vite 开发服务器把 `/api` 代理到 `http://localhost:8080`。
4. 后端 `AuthInterceptor` 检查 token 和角色。
5. `PathController` 校验 `from`、`to`，调 `PathService`。
6. `PathService` 从 `CityService` 拿当前图和 `graphVersion`，查缓存；版本不对就调 `DijkstraShortestPath`。
7. `Dijkstra` 返回 `PathResult`，`PathService` 转成 `PathDTO`。
8. `Controller` 包成 `Result`，返回 JSON。
9. 前端 axios 拦截器取 `data`，页面渲染路径和代价。

## 7. 核心数据怎么流

```
cities.txt
   │  启动时读，UTF-8，3 列
   ▼
CityService / 双向循环链表        ← 城市的主数据
   │  派生
   ▼
WeightedGraph / 邻接表            ← 完全图，30 城 435 条边
   │
   ├──► Prim / Kruskal ──► MST 结果（29 条边）
   │
   └──► Dijkstra ────────► 路径结果
                              │
                              ▼
                    API / 页面 / ConsoleRunner
```

**关键点：**

- 链表是主数据，图从链表派生，不要让两边各改各的。
- 任何写操作走 `CityService`，改完 `graphVersion++`。
- MST 和路径缓存都带 `graphVersion`，版本不对就重算。
- 30 城全量重算很快，不做增量。

## 8. 每个包放什么、不放什么

| 包 | 放什么 | 不放什么 |
|---|---|---|
| `controller` | `CityController`、`GraphController`、`MstController`、`PathController`、`AuthController`、`AdminController` | 算法、数据结构、SQL |
| `service` | `CityService`、`GraphService`、`MstService`、`PathService`、`AuthService` | HTTP 细节、页面逻辑 |
| `model` | `City`、`Edge`、`User` | `prev/next` 指针、DTO 字段 |
| `dto` | `CityDTO`、`AdjacencyDTO`、`MstDTO`、`PathDTO`、`LoginRequest/Response` | 内部结构、链表指针 |
| `structure` | `CityNode`、`DoublyCircularLinkedList`、`WeightedGraph` | Spring 注解、Controller |
| `algorithm/mst` | `PrimMST`、`KruskalMST`、`UnionFind` | 图存储、HTTP |
| `algorithm/path` | `DijkstraShortestPath` | 图存储、HTTP |
| `common` | `Result`、`ResultCode`、`GlobalExceptionHandler` | 业务逻辑 |
| `config` | `WebConfig`、`AuthInterceptor` | 算法 |
| `auth` | `Role`、`RequireRole` | 用户数据 |
| `exception` | 自定义异常 | 全局处理器（放 common） |
| `util` | `DistanceUtil` | 业务状态 |
| `cli` | `ConsoleRunner` | Web 依赖 |
| `benchmark` | `BenchmarkRunner` | 生产接口 |

## 9. 版本说明（重要）

当前骨架用的是**本机已安装的版本**：

| 项 | 统一版本 | 说明 |
|---|---|---|
| JDK | 25 | 本机已装，文档 v1.1 也改成了 25 |
| Spring Boot | 4.1.2 | 与 JDK 25 匹配 |
| Node.js | 24 | 本机已装，文档 v1.1 也改成了 24 |
| Maven | 3.10（wrapper） | 用 `mvnw`，不装全局 Maven |
| Vite | 5.x | 前端构建 |

**为什么骨架用 25/4.1.2：** 本机只装了 JDK 25，`demo` 也是用 25 + Boot 4.1.2 生成的。用这套能直接跑。

**如果课程要求 JDK 21：**

1. 安装 JDK 21。
2. 改 `logistics-server/pom.xml`：
   - `<java.version>21</java.version>`
   - `<parent>` 的 `<version>` 改成 3.5.x（或老师指定的版本）。
3. 代码不用改。
4. 同步改文档 v1.1 的 1.3 技术栈表（JDK 21 / Boot 3.5.x）。

> 不要在同一个项目里混用 21 和 25 的编译产物。选一个，全组统一。

## 10. 怎么启动

### 后端

```powershell
cd logistics-server
.\mvnw.cmd spring-boot:run
```

- 端口 8080。
- 第一次运行会下载 Maven 和依赖，需要网络，耐心等。
- 启动类：`com.logistics.LogisticsApplication`。

### 前端

```powershell
cd logistics-web
npm install
npm run dev
```

- 端口 5173。
- `/api` 自动代理到 `http://localhost:8080`。
- 先 `npm install`，再 `npm run dev`。

### 建议顺序

1. 先启动后端，确认 8080 能访问。
2. 再启动前端，确认 5173 能打开。
3. 登录页能打开，说明路由和布局没问题。
4. 后端接口没好之前，前端用 `src/mock/` 的数据。
