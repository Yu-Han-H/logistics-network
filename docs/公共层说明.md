# 公共层说明

> 目的：说明 `common`、`exception`、`auth` 这几层是干什么的，为什么可以直接实现，以及怎么读。
> 这一层不是课程要求手写的数据结构/算法，是 Web 接口的“公共管道”。

## 1. 为什么可以直接实现

课程的红线是：

- 双向循环链表、邻接表、Prim、Kruskal、Dijkstra 必须手写。
- 不能用 JGraphT 等第三方算法库。

这些已经在 `structure/`、`algorithm/` 里完成，33 个测试通过。  
`common/`、`dto/`、`controller/` 是 Spring Web 的接口层，不属于“手写数据结构”的评分点。它们的作用是：

- 让三个人的接口返回格式一致；
- 让异常统一变成 400/401/403/404/409/500；
- 让前端只按 `docs/api.md` 对接。

如果三个人各写一套 `Result`、各写一套 try/catch，最后一定对不上。所以**公共层由一个人实现、其他人 review**，是更稳的做法。

这不影响对项目的理解，前提是：

1. 每个人知道一次请求怎么走：`Controller → Service → structure/algorithm → Result`。
2. 每个人知道异常怎么变成 HTTP 码：`Service 抛异常 → GlobalExceptionHandler → Result`。
3. 每个人知道 `graphVersion` 是谁维护的：`CityService`。

## 3. FieldError 为什么是空的

`FieldError` 是 Java 的 **record**，不是普通类：

```java
public record FieldError(String field, String message) {
}
```

空方法体是正常的。编译器会自动生成：

- 构造方法 `FieldError(String field, String message)`；
- 访问器 `field()`、`message()`；
- `equals()`、`hashCode()`、`toString()`。

它只负责“装一条字段错误”，不负责“收集错误”。  
收集发生在 `GlobalExceptionHandler`：

```java
List<FieldError> errors = ex.getBindingResult().getFieldErrors().stream()
    .map(fieldError -> new FieldError(fieldError.getField(), fieldError.getDefaultMessage()))
    .toList();
```

`Result` 也是 record：

```java
public record Result<T>(int code, String message, T data, List<FieldError> errors) {
    public static <T> Result<T> ok(T data) { ... }
    public static <T> Result<T> fail(...) { ... }
}
```

`code()`、`message()`、`data()`、`errors()` 是自动生成的访问器；`ok/fail` 是手写的静态工厂方法。

## 4. 一次请求怎么走

以“新增城市”为例：

```text
POST /api/cities
   │
   ▼
CityController.add(@Valid CityRequest)
   │  参数不合法 → MethodArgumentNotValidException
   │  参数合法   → cityService.add(request)
   ▼
CityService.add
   │  名称重复 → DuplicateCityException
   │  坐标非法 → InvalidCoordinateException
   ▼
返回 CityDTO
   │
   ▼
Result.ok(cityDTO)
   │
   ▼
HTTP 200 + {code:200, message:"success", data:{...}}
```

异常路径：

```text
Service 抛 CityNotFoundException
   │
   ▼
GlobalExceptionHandler.handleCityNotFound
   │
   ▼
HTTP 404 + {code:404, message:"城市不存在：9999", data:null}
```

## 5. 怎么加一个新异常

1. 在 `exception/` 新建 `XxxException extends RuntimeException`。
2. 在 `GlobalExceptionHandler` 加一个 `@ExceptionHandler(XxxException.class)` 方法，返回对应的 `Result.fail(...)` 和 HTTP 状态。
3. 在 `docs/api.md` 的状态码/错误示例里补一行。
4. 在 Service 里抛这个异常，不要在 Controller 里 `try/catch`。

## 6. 怎么加一个字段校验

1. 在 `dto/CityRequest.java` 的字段上加注解，例如：
   ```java
   @NotBlank(message = "城市名称不能为空")
   String name
   ```
2. Controller 参数加 `@Valid`。
3. 校验失败会自动进 `GlobalExceptionHandler`，返回 400 + `errors` 数组。
4. 不需要在 Service 里再写一遍“非空”判断；但“名称唯一”这种跨数据的校验要放 Service。

## 7. 为什么 AuthInterceptor 现在是放行

因为登录逻辑还没实现。先放行，前端可以用 mock 联调；等 `AuthService` 补完：

1. 从 `Authorization: Bearer <token>` 取 token；
2. 无效/缺失抛 `UnauthorizedException`（401）；
3. 读 `@RequireRole`，角色不符抛 `ForbiddenException`（403）；
4. 把当前用户放到 request attribute。

## 8. 读代码的顺序

1. `ResultCode`：看状态码。
2. `Result`：看成功/失败怎么包。
3. `FieldError`：看字段错误长什么样。
4. `GlobalExceptionHandler`：看异常怎么变 HTTP。
5. `AuthInterceptor`：看登录检查的 TODO。
6. `docs/api.md`：看最终 JSON。

## 9. 这一层不做什么

- 不写链表、图、MST、Dijkstra。
- 不写业务规则（名称唯一、坐标范围、版本号）。
- 不直接改 `structure/`、`algorithm/`。

## 10. 一句话

公共层是“接口管道”，不是“数据结构”。可以直接实现，但每个人要能讲清一次请求和一次异常是怎么走的；讲不清就 review 这 5 个文件，而不是重写一套。
